# M2 task plan: Tool registry and audit

**Goal**: Every action by a person, an AI agent, a partner company or the system goes through one tool registry and leaves one audit row with an actor. The 14 existing MCP tools move onto the registry with their names unchanged. Workflow actions stop writing orders with raw Prisma calls.

**Done when** (PRD §10, made testable):
1. Integration test `mcpAudit.test.ts` calls each of the 14 tools over stdio and over `POST /mcp`. Each call writes exactly one `AuditLog` row with actor id, `actorKind`, `channel = mcp`, tool name, redacted input, status (`ok`, `denied`, `invalid`, `error`) and duration.
2. A key whose role does not allow a tool: `tools/list` does not show it, a call returns an error, and the audit row has status `denied`.
3. The 14 tool names and input fields are unchanged. The existing `mcpOrdersUpdateStatus` test passes, including the backdated `deliveryDate`.
4. A test fails if a tool is registered outside the registry. An ESLint rule fails the build if a tool handler imports `prisma`.
5. Rate limit: the 31st call in a minute from one key is refused with `retryAfterSeconds`; the 301st call in a minute from one tenant is refused; the counter survives a server restart (Redis).
6. `SYSTEM_USER_ID` is gone. Every tenant has one `User` with `kind = system` that cannot log in.
7. A test fails if a workflow action calls `prisma.order.update`. `update_order` and `assign_agent` produce `OrderHistory` rows through the services.
8. A revoked MCP key stops working in 60 seconds or less.

**Depends on**: M0 (tenant scoping, `seedTenantDefaults`), M1 (`transitionOrder`, KPI services, `Finding`).

**PR**: one PR for the whole milestone. Branch `feature/m2-tool-registry-audit` from `develop` (after M1 is merged), into `develop`. Never push to `main`. No push before owner approval.

**Owner of every task**: builder, with Opus review.

Legend: XS = 2 h, S = 3-4 h, M = 5-6 h, L = 7-8 h. Run `npx prisma generate` first. Hand-migrate the test database after each new migration. Jest with `--forceExit`.

Models that M6 owns but M2 needs early (minimal shape only): `Role` and `RoleAssignment`. M6 adds the screens, the 16 tool switches and the permission grid. M6 must not create these models again.
