# M10: Delivery agent app

- **Goal:** A delivery agent uses a separate phone app. They see their orders, complete or fail a delivery, confirm stock they receive, see the delivery fees they kept, and report cash deposits. English only (D1).
- **Done when** (from PRD section 10, made testable):
  - On a 390 px phone, an agent starts a delivery, completes it with the cash collected and who received it, and the order shows delivered in the admin app. The agent's held cash rises by the amount collected.
  - The agent confirms received stock on a transfer. If fewer units arrive, the transfer becomes `disputed` and the office gets an inbox item. Confirmed stock shows on the agent Stock page and in `StockLevel`.
  - The agent deposit needs a unique reference number. A deposit above the cash held is refused with "You hold GH₵X. You cannot deposit more."
  - "Fees you kept" shows the delivery fees from `Order.deliveryFee` for the month. No screen shows "pay owed" or "agent pay".
  - Every action updates every number that shows it (Home, header, lists) without a reload. The old `/m` routes and the "Mobile View" switch are gone.
  - A blocked or paused agent sees the pause message on every tab and cannot start deliveries.
- **Depends on (milestones):** M0 (delivery route access, tenant isolation), M1 (state machine, reasons), M3 (shell, routing behind the flag `features.agentApp`, turned on in M10-T08), M4 (transfer receipt API, `StockLevel`, partner screens), M5 (`Order.deliveryFee`, deposit flow, `AgentCollection`), M6 (targets and rewards for progress), M9 (inbox services and notification preferences)
- **PR:** one PR for this milestone. Branch `feature/m10-delivery-agent-app` from `develop`, PR into `develop`. Never push to `main`. Do not push before the owner approves.
- **Owner of every task:** builder, with Opus review. No owner column.
- **Source:** `docs/prd/PRD.md` sections 5, 6, 7, 10, 11; `docs/prd/decisions.md`; the area files named in the F-IDs; design doc section 10.
- **Size key:** XS = 2 h, S = 3 to 4 h, M = 5 to 6 h, L = 7 to 8 h. Anything larger is split.
- **Working rules:** `codadmin/CLAUDE.md` applies. Run `npx prisma generate` before `tsc` (a stale client hides type errors). After each migration, apply it by hand to the test database `ecommerce_cod_test` (`cd backend && DATABASE_URL=$(grep -E '^DATABASE_URL=' .env.test | sed 's/^DATABASE_URL=//;s/"//g') npx prisma migrate deploy`); the test setup has no global migrate. Run jest with `--runInBand --forceExit`. Feature branches only; PR into `develop`.

**Schema note.** This milestone adds no new tables. The only migration is one unique index (T05). All other data comes from M4, M5, M6 and M9.
