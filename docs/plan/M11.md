# M11: AI chat, read only

- **Goal:** An AI drawer on every admin screen answers number questions from the KPI services and lists open problems. Suggestion cards open pre-filled screens and never change data. The audit log has a screen.
- **Done when** (from PRD section 10, made testable):
  - Asked "What was delivered revenue in October?", the chat returns the same number as the Dashboard and the KPI service, and names the tool it used. Every number in an answer appears in a tool result (grounding test with a stub model).
  - Asked "What problems are open?", the chat lists open Findings and the problem-finder results (cash gaps by partner, stock gaps by location, unmapped campaigns, slow queue, orders waiting to dispatch) with a link to the right screen.
  - The model never sees a full customer phone number or street address. Free text in orders, notes and messages cannot make the model call a tool the user did not ask for.
  - No card click and no chat call changes business data. A test per card checks that no write request fires on click. Dismiss and snooze store only a per-user preference.
  - The audit-log screen (Staff and roles) shows every actor, channel, tool and status for the owner and admin, with filters (R13).
  - Cards whose data source does not exist stay hidden. "Cut budget" and "Raise budget" cards read "Open campaign" (no Meta write).
- **Depends on (milestones):** M0, M1 (KPI services), M2 (tool registry, audit log API, rate limits F-1305), M3 (shell, command palette), M4 to M10 (data for the finders: stock, Findings, partner settlements, rep queue, Meta spend, conversations, workflows, roles). Cards for a screen stay hidden until its data exists.
- **PR:** one PR for this milestone. Branch `feature/m11-ai-chat-read-only` from `develop`, PR into `develop`. Never push to `main`. Do not push before the owner approves.
- **Owner of every task:** builder, with Opus review. No owner column.
- **Source:** `docs/prd/PRD.md` sections 5, 6, 7, 10, 11; `docs/prd/decisions.md`; the area files named in the F-IDs; design doc section 10.
- **Size key:** XS = 2 h, S = 3 to 4 h, M = 5 to 6 h, L = 7 to 8 h. Anything larger is split.
- **Working rules:** `codadmin/CLAUDE.md` applies. Run `npx prisma generate` before `tsc` (a stale client hides type errors). After each migration, apply it by hand to the test database `ecommerce_cod_test` (`cd backend && DATABASE_URL=$(grep -E '^DATABASE_URL=' .env.test | sed 's/^DATABASE_URL=//;s/"//g') npx prisma migrate deploy`); the test setup has no global migrate. Run jest with `--runInBand --forceExit`. Feature branches only; PR into `develop`.
