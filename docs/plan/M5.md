# M5: Settlement and finance

- **Goal:** Finance shows true unpaid cash. Delivery fees are booked once. A partner payout recorded by an outside agent reconciles with no hand step. Money out to people uses one payout form. Online payment, the provider interface and the checkout forms moved to M3b.
- **Done when** (from PRD section 10, made testable):
  - The aging card counts only delivered orders with no reconciled collection. The 1,321 old draft collections are reconciled by a backfill that uses app data only (no portal export), and a before and after count is in the PR.
  - One generic "record partner payout" call (API route or MCP tool, any delivery partner, no partner-specific code; decisions O1 and O7) called with a normal API or MCP key that holds the payout permission, with a paid-order list plus a payout creates one `PartnerSettlement`, matches every line to an order, moves matched collections to `reconciled`, records one `AgentDeposit` for the net amount, and opens a `Finding` for any gap. No person clicks anything.
  - On the fixture the expected payout is cash collected minus fees (decision F4). Kofi's fee rule of GH₵25 per delivered order is booked once to 5070 on delivery. Account 1020 stays at 0. Account 1010 does not rise twice for the same cash.
  - The Finance Overview shows six tiles, payout reconciliation, unpaid by age, Findings, monthly P&L with the Aug and Sep note, and October margin of about -16% on the fixture (R6).
  - One payout form pays rep commission, upsell reward and target reward. It has no delivery fee line. Adwoa shows owed GH₵2,034 and Nana GH₵134 on the fixture.
  - Paid digital orders (M3b) feed the Finance numbers: delivered revenue includes account 4020 and the Paystack fee on 5060 (fixture test in M5-T24).
- **Depends on (milestones):** M0 (Decimal money, tenant isolation, per-tenant chart seed), M1 (KPI services, order state machine, `deliveryDate`, `returnedAt`, `FxRate`), M2 (service paths so fee posting is not bypassed), M3b (provider interface, neutral webhook, `PaymentConnection`, provider fee hook to 5060 and 1030), M4 (partners list and `DeliveryPartnerProfile`, `StockLocation`, `StockCount`). `Finding` and `FeeRule` come from M1-T02 and are extended here.
- **PR:** one PR for this milestone. Branch `feature/m5-settlement-and-finance` from `develop`, PR into `develop`. Never push to `main`. Do not push before the owner approves.
- **Owner of every task:** builder, with Opus review. No owner column.
- **Source:** `docs/prd/PRD.md` sections 5, 6, 7, 10, 11; `docs/prd/decisions.md`; the area files named in the F-IDs; design doc section 10.
- **Size key:** XS = 2 h, S = 3 to 4 h, M = 5 to 6 h, L = 7 to 8 h. Anything larger is split.
- **Working rules:** `codadmin/CLAUDE.md` applies. Run `npx prisma generate` before `tsc` (a stale client hides type errors). After each migration, apply it by hand to the test database `ecommerce_cod_test` (`cd backend && DATABASE_URL=$(grep -E '^DATABASE_URL=' .env.test | sed 's/^DATABASE_URL=//;s/"//g') npx prisma migrate deploy`); the test setup has no global migrate. Run jest with `--runInBand --forceExit`. Feature branches only; PR into `develop`.

**Scope note.** This milestone holds finance (area 10) and fee rules and settlement (area 07). The payments group (provider interface, neutral webhook, provider fee hook, form payment rules, callback page) moved to its own milestone, M3b (`docs/plan/M3b.md`). Task IDs T01, T20, T21, T22, T23 and T43 moved there and are not reused, so every other ID keeps its number. T09 (partner key service) and T33 (partner key card) were removed by decision O7 and are not reused.
