# M6: Roles, targets, rewards

- **Goal:** The owner sets a North Star once and sees targets split by quarter, month, role and person. Roles and permissions are per tenant. Staff are invited, not created with a password. Rewards are earned at month close.
- **Done when** (from PRD section 10, made testable):
  - The Targets page shows, for every role and every person, a status of on track or off track against the month target, with margin beside revenue at each level.
  - On the fixture the North Star setup gives: annual GH₵1.8M; quarters 360k, 420k, 480k, 540k on "grow each quarter"; October GH₵180,000 / GH₵249 = 723 delivered; 1,721 orders; 56 orders a day (31 days, R2).
  - Month close is a job. A dry-run preview shows reward entries from `RewardTier` (cash tiers only: rep 100% GH₵300, 120% GH₵500 plus a paid day off; delivery 100% GH₵250, 120% GH₵400 plus a paid day off). Running it twice creates entries once.
  - The seven current roles map to position roles with no loss of access (test: every user keeps every permission they had). Effective permission is the union of the roles held.
  - An invited person sets their own password. A deactivated user cannot sign in. The last Owner cannot be deactivated.
  - The round-robin position survives a server restart.
- **Depends on (milestones):** M0 (tenant isolation, Decimal), M1 (KPI services, `FxRate`, state machine), M2 (MCP keys tied to a user and a role, `User.kind`), M3 (shell, menu, Settings shell), M4 (partners data), M5 (payout form, `CommissionEntry` posting, account 2020 and 5050)
- **PR:** one PR for this milestone. Branch `feature/m6-roles-targets-rewards` from `develop`, PR into `develop`. Never push to `main`. Do not push before the owner approves.
- **Owner of every task:** builder, with Opus review. No owner column.
- **Source:** `docs/prd/PRD.md` sections 5, 6, 7, 10, 11; `docs/prd/decisions.md`; the area files named in the F-IDs; design doc section 10.
- **Size key:** XS = 2 h, S = 3 to 4 h, M = 5 to 6 h, L = 7 to 8 h. Anything larger is split.
- **Working rules:** `codadmin/CLAUDE.md` applies. Run `npx prisma generate` before `tsc` (a stale client hides type errors). After each migration, apply it by hand to the test database `ecommerce_cod_test` (`cd backend && DATABASE_URL=$(grep -E '^DATABASE_URL=' .env.test | sed 's/^DATABASE_URL=//;s/"//g') npx prisma migrate deploy`); the test setup has no global migrate. Run jest with `--runInBand --forceExit`. Feature branches only; PR into `develop`.
