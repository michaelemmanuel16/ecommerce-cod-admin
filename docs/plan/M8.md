# M8: Marketing

- **Goal:** CodAdmin pulls Meta ad spend by itself, maps each campaign to a product, books the spend, and shows spend, funnel, max CPA and campaign status. The numbers match Ads Manager.
- **Done when** (from PRD section 10, made testable):
  - For one test week, daily spend, impressions, link clicks, landing page views and checkouts started per campaign in CodAdmin equal the Ads Manager export for the same week and account (spend within 0.5% after the daily re-pull).
  - An hourly job updates today's spend. A daily job at 05:00 Accra time re-pulls the last 3 days (R7). Both are idempotent: a second run changes no row.
  - Spend is held in the ad account currency and converted to the store currency at the day rate (`FxRate`; the original amount and currency stay on the row; decision O5). The ₦ and GH₵ figures below are sample values for the Manny Dynamics store. Each day posts DR 5080, CR 1010. A re-pull that changes a day posts only the difference.
  - Every campaign has a status: Winning, On track, Over max CPA, Not mapped or Paused. Max CPA on the fixture is ₦7,040 for the account at 34% yield (profit per delivered order before ads x yield, using the weighted fee from fee rules, R5).
  - An unmapped campaign shows "Not mapped" and its spend still counts in the totals.
  - The Meta App Review and scope result is written down before the pull code starts (early risk task).
- **Depends on (milestones):** M1 (order-to-cash yield on closed cohorts, `FxRate`), M3 (Reports shell, Settings shell), M3b (public checkout and the Checkout forms list that M8-T08 and M8-T18 extend), M5 (account 5080, fee rules for the weighted fee, Finance cards), M6 (marketing role mapping)
- **PR:** one PR for this milestone. Branch `feature/m8-marketing` from `develop`, PR into `develop`. Never push to `main`. Do not push before the owner approves.
- **Owner of every task:** builder, with Opus review. No owner column.
- **Source:** `docs/prd/PRD.md` sections 5, 6, 7, 10, 11; `docs/prd/decisions.md`; the area files named in the F-IDs; design doc section 10.
- **Size key:** XS = 2 h, S = 3 to 4 h, M = 5 to 6 h, L = 7 to 8 h. Anything larger is split.
- **Working rules:** `codadmin/CLAUDE.md` applies. Run `npx prisma generate` before `tsc` (a stale client hides type errors). After each migration, apply it by hand to the test database `ecommerce_cod_test` (`cd backend && DATABASE_URL=$(grep -E '^DATABASE_URL=' .env.test | sed 's/^DATABASE_URL=//;s/"//g') npx prisma migrate deploy`); the test setup has no global migrate. Run jest with `--runInBand --forceExit`. Feature branches only; PR into `develop`.
