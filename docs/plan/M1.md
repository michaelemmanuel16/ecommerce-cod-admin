# M1 task plan: KPI definitions

**Goal**: One answer for every number. Build the KPI service layer, the rebuilt order state machine, the order timestamps and `FxRate`. Check all of it against one fixed fixture that reproduces `docs/mockups/v2/NUMBERS.md`.

**Done when** (PRD §10, made testable):
1. Contract test `backend/src/__tests__/integration/kpiContract.test.ts` runs on the fixture. The dashboard-facing KPI routes, `/api/analytics/*`, `GET /api/financial/summary`, the product performance revenue column, and MCP `orders_summary`, `analytics_daily`, `analytics_weekly`, `analytics_monthly`, `financial_summary` all return delivered revenue `92000.00` and 376 delivered orders for 1 to 17 October 2026.
2. KPI unit tests on the fixture: confirmation rate 71% (1,026 / 1,445); delivery success rate 48% (376 / 778); order-to-cash yield 34%; orders needed a day 56 for October (31 days); AOV GH₵245; projected month GH₵167.8k; needed a day GH₵6.3k.
3. Rep rates on the fixture: Adwoa 253 / 486 = 52%, Confirm agent 110 / 249 = 44%, Nana 13 / 43 = 30%, all 376 / 778 = 48%. A payout does not change them.
4. Product delivered units: copybook set 306, refill pens 172, pencil grip trainer 89, guide 58, Dictamni cream 10.
5. `transitionOrder` is the only code that writes `Order.status` (grep test with a named allow-list). Invalid move gives 409 `INVALID_TRANSITION`. Stale write gives 409 `STALE_ORDER`.
6. Failed-delivery journal entry posts once on every path (app, delivery route, MCP, import).
7. Backfill script prints counts of filled and empty rows for `confirmedAt`, `dispatchedAt`, `firstContactAt`, `returnedAt`.
8. Nightly order-versus-ledger job creates no Finding on the fixture.
9. FX daily job stores a row with source `auto`; a manual rate stores source `manual`; a store currency change is saved at any time and later figures convert by the record date (O6).
10. The wording guard test fails the build on `airtime`, `delivery rate` or `6,400` outside the allow-list.

**Depends on**: M0 (tenant-scoped models, `Money` helper, Decimal columns, `withoutTenant`).

**PR**: one PR for the whole milestone. Branch `feature/m1-kpi-definitions` from `develop` (after M0 is merged), into `develop`. Never push to `main`. No push before owner approval.

**Owner of every task**: builder, with Opus review.

Legend: XS = 2 h, S = 3-4 h, M = 5-6 h, L = 7-8 h. Run `npx prisma generate` first. Hand-migrate the test database after each new migration (see M0 header). Jest with `--forceExit`.

Models that other milestones own but M1 needs early (minimal shape only): `Target` (F-253 reads it), `Finding` (F-905 writes it), `FeeRule` (F-303 and F-935 read it), `FxRate` (F-1232). M6, M5 and M5 add their screens and rules later. They must not create these models again.
